Selected work

Six problems I found, what I did about them, and what changed. Each one comes from live ERP and IT operations work.

Getting faculty to use the LMSMastersoft ERP, LMS module

Problem
Faculty, many of them senior doctors, rarely used the LMS to set assignments. The module needed too many clicks and had steps nobody needed.
Action
I ran several training sessions and collected what faculty found hard. Then I showed the vendor that the workflow itself was the problem, not just training, and recommended removing the unnecessary steps.
Result
Faculty adoption rose from about 40% to about 85%.

One attendance record for every online classMicrosoft Teams and ERP integration

Problem
Online classes ran on Teams, but students often joined with personal email addresses, so their student numbers were not captured.
Action
I defined how Teams users map to the student master, what happens to unmatched emails, and how to block a duplicate login on a shared link. I also specified how repeated joins and leaves combine into one record.
Result
Attendance is built around one verified record per student per class, based on actual active time.

Designing the learning modulesAcademic, OBE and feedback modules

Problem
The institution needed course offering, teacher allotment, registration, timetables and outcome tracking to run inside the ERP, with students and faculty able to finish tasks easily.
Action
I wrote the BRDs and SRS, designed the process flows for faculty, student and administrator journeys, and designed the Course Outcome and Program Outcome (OBE) module. I configured the masters, ran UAT and trained users.
Result
Course outcomes link to program outcomes in the system, and a feedback module collects student and faculty views. Satisfaction improved because tasks became easier.

A production issue, fixed safelyERP resignation workflow

Problem
After go-live, a workflow that had passed UAT showed employees’ resignation details to every user.
Action
I treated it as urgent, rolled the workflow back and had the vendor stop the feature. The permanent fix followed a root-cause analysis, a change request, a fix, UAT, approval and validation in production.
Result
The exposure was contained straight away and the workflow returned with the access problem fixed.

Telling hospital admins who is on leave tomorrowHospital operations dashboard

Problem
Administrators could not see which doctors would be absent the next day, so patients reached the OPD and only then found out.
Action
I built a doctor leave and attendance dashboard for building administrators.
Result
Administrators plan the next day’s OPD in advance.

Cutting a connection check from 15 minutes to 1Accenture, managed file transfer

Problem
Checking a subscriber connection meant logging in by hand, and each check took 10 to 15 minutes.
Action
The folder already had its rule configured, so I proposed dropping a dummy test file into it and letting the rule send the result by email.
Result
The check takes about one minute with no manual login.
